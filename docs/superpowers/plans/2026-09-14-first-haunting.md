# The First Haunting — implementation plan

User approved the one-encounter Milestone 2 proposal and then selected `gpt-5.6-luna` through ChatGPT OAuth (`openai-codex`), with the proposed $1 / twenty-model-request ceiling. Work stays inline. No paid API or provider fallback is authorized.

## Scope and order

- [ ] **Pinned model connection and live smoke.** Add `chaos/oauth.py`, unit tests `tests/chaos/test_oauth.py`, and an explicit CLI route. Consume the installed Hermes Codex auxiliary client without constructing an agent, injecting tools, changing the default model, or copying credentials. Use a persistent request ledger, reserve before calls, no retry, verify endpoint/model, bound prompts and request lifetime. Subscription usage is not a dollar invoice: retain actual token counts and label cash billing as unreported, with paid API fallback prohibited. Run one real decision against actual game event evidence and verify engine acceptance; stop on authentication/rate-limit failure rather than switching providers.
- [ ] **Narrow Lua decision runtime.** Add `include/chaos_lua.h` and `src/chaos_lua.c`; tests compile the real Lua adapter. Source is text-only and bounded. No standard libraries, native pointers, file/process/network capabilities or catches for resource exhaustion. A fresh interpreter per decision reads copied bounded history and returns only a movement intent plus typed serializable state. Reject malformed results before any engine mutation. Test loops, memory exhaustion, forbidden access, result bounds, state and determinism.
- [ ] **One real encounter.** A designated weak creature pursues the player's delayed footsteps using the hand-authored Lua handler. Track only the bounded history needed, scoped to a dungeon level. The C engine checks and executes movement; scripts cannot change attacks, damage, inventories or arbitrary state. Use a telegraphed, reversible activation and persistent source/state/target identity. Tests must call real game movement paths, not merely the Lua math.
- [ ] **Targeted Dreamlands validation.** Fork an isolated copy of the live C simulation to exercise the candidate with a bounded bot and the same runtime/engine movement path. Report actual shadow outcomes through a bounded pipe; parent state and random generator must be unchanged. No live file writes, terminal prompts or external calls from the shadow. Enforce process timeout and reject unsafe candidates. This is targeted encounter evidence, not full-game proof of fairness or reachability.
- [ ] **Cosmetic echoes.** Actual shadow events, including rejected candidates, may queue a registered recollection at a defined perceptual trigger. Keep this presentation state separate from game mechanics and mandatory mutation telegraphs. No gameplay random draws, time, damage, sanity, budget changes, hidden state disclosure or unsolicited acknowledgement prompts. Test paired runs with echoes enabled/disabled for identical gameplay state.
- [ ] **Model-composed candidate.** Only after the hand-authored behavior and shadow gates pass, ask Luna for a short program targeting the same interface. Validate the exact returned source and exercise it in the game. A generated candidate may legitimately be rejected; retain evidence and do not substitute a hand-authored program while labeling it generated.
- [ ] **Acceptance and publication.** Run old and new tests, both builds, real terminal encounter/save/restore and controlled replay, Python lint and inline review. Document actual outcomes, costs/usage, limitations and play commands. Commit and verify GitHub publication only when the named scope is exercised, or report the exact remaining blocker.

## Test discipline

Write failing tests before each production component, run the focused tests, implement, rerun, then exercise the real integration. Preserve failed probes when they explain a limitation. Do not turn user-facing design prose into claims of completed behavior. Native scripting, engine legality, shadow execution, harmless echoes and live model use are separate acceptance items.

## Resource and safety boundaries

The twenty-request counter covers all NyarlatHack model inference attempts for this milestone across processes, including failures. No tool calls are supplied to the model. OAuth refresh is delegated to the existing root-managed Hermes credential machinery. No new profile, gateway restart, global model change or credential copy is needed. Test assets and local dependency installation are scoped to this project; no public-server deployment is included.
