A model-authored curio, from trigger to reveal, in ordinary play

Tier A. In live attempt 013, a real trigger led to one Grok 4.7 request. The engine admitted the curio, placed it on a fresh main-dungeon level, and the player picked it up, inspected it and applied it (Sanity −1). The on-screen reveal reported it. A model-free replay reproduced every input, every native event, the admission index and source checksum, the reveal and the game log byte for byte. The copied save matched apart from the per-game transport token.

A curio is an object whose Lua source a model writes. The engine validates and runs that source. The director is the separate process that proposes it. A safe point is an engine-controlled moment at which a proposal can be admitted.

What ran

A nonwizard ordinary Bard game on seed 12, launched as chaos play --ordinary --author-provider xai-oauth --author-model grok-4.7 --curio-validator VALIDATOR under Hermes's runtime. The default hound and next-use lanes were on. The separately named screen-reading player curio-capture-v1 drove the game; the gate policy baseline-v2 was not changed. Between actions the harness paused 0.12 s for transport, and it paused wall time while the author request was pending. It never forced the trigger and never advanced game time. Engine, launcher and validator were built from ff4adf393. Every later commit changes only the test player and evidence.

How the seed was chosen. I used only the public seed-sweep-v2-179 report: bard-default-path rows with outcome turn_limit and a recorded DL3 arrival, ordered by earliest DL3 turn, excluding seed 1 (attempt 001). Attempt 002 took the first row, seed 12; attempt 003 took seed 89. On seed 12 the trigger fired at a stable public turn (356), so attempts 004–013 deliberately repeated it while the player was fixed. No hidden map state was read.
